# backend/prisma

This directory holds the authoritative Prisma schema (`schema.prisma`), transcribed
verbatim from `docs/architecture/data-model.md` (section "Finalized Prisma schema").

## Migrations

The initial migration is **not** committed here. It is generated by the orchestrator
on the host using `prisma migrate diff` (or `prisma migrate dev`) because the sandbox
has no network access and no running PostgreSQL instance.

Do not run `prisma migrate dev`, `prisma migrate deploy`, or `prisma db push` inside
the sandbox — they require a live database.

### Why the orchestrator generates it

- Sandbox: network `none`, no Postgres.
- `prisma migrate diff` needs an empty target DB (or `--from-empty`) to emit the SQL.
- The host provisions dependencies and runs build/test afterwards.

### Reference

- Source of truth: `docs/architecture/data-model.md` → "Finalized Prisma schema (Phase 1 authoritative)".
- Schema defines: enums `Region`, `GameMode`, `Difficulty`, `GameStatus`,
  `RoundStatus`, `LocationSrc`, `WeatherSrc`; models `Location`,
  `WeatherSnapshot`, `Game`, `Round`, `Guess`, `Result`, `Challenge`,
  `ChallengeEntry`.

Account migration `20261115150000_user_auth` is additive. Existing games keep their
anonymous player-token hashes and receive a nullable `ownerUserId`; account deletion
sets that relation to null and cascades only identity, sessions, reset tokens, and
preferences. Existing games/results remain under R18 retention.
